سجل الأخطاء والتصحيح (Debugging & Verification)

المشاكل الـ 5 التي واجهتنا أثناء البناء وكيف تجاوزناها في ModelSim

1. مشكلة ناتج الجمع (4 بدل 14) وغياب الطرح alu_1bit.v

السبب: إشارة اختيار الموّزع S كانت 1-bit فقط ومربوطة لتمريير المدخل B بشكل دائم عند `0`.
الحل: توسيع التحكم لـ 2-bit (`S[1:0]`) وإضافة بوابة XOR مع `S[0]` وتمرير `carryIn = S[0]` لتنفيذ متمم الاثنين ($A - B = A + \sim B + 1$).

2. إشارة التحكم المعلقة (alu_ctrl = X باللون الأحمر) control_unit.v

السبب: شرط فحص `funct7[30]` كان موضوعاً بالخطأ داخل تعليمات القيم الفورية I-Type بدل R-Type، وغياب تغطية `default:` كاملة.
الحل: تصحيح موقع الشرط تحت `opcode == 7'b0110011` وتغطية كافة المخارج في `default: alu_ctrl = 2'b00;` لتجنب توليد Latch.

3. ثغرة الكتابة فوق السجل الصفري (x0 Overwrite Vulnerability) register_file.v

السبب: غياب شرط يمنع كتابة البيانات إذا كان عنوان السجل المستهدف `rd == 5'd0`.
الحل: حماية هاردوير مستقيمة `if (we && rd != 5'd0) registers[rd] <= wd;` تجعل السجل `x0` ثابتاً على الصفر دوماً.

4. خطأ توقيت المحاكاة في ModelSim وقراءة العينات riscv_tb.v

السبب: زر Run الافتراضي يمشي 100ps وهي غير كافية للدورة، وقراءة قيم السجلات عند حافة الصعود بالضبط كشفت Race Condition.
الحل: أخذ العيّنات بفارق زمني في منتصف النصف السالب للساعة (`#3` بعد `posedge clk`) لضمان استقرار الإشارات.

5. خطوط البيانات المجهولة (XXXX) بآخر الذاكرة instruction_memory.v

السبب: وصول عداد الرمز `PC` لخانات غير محددة بالذاكرة بعد انتهاء البرنامج.
الحل: وضع تعليمة `NOP` (`32'h00000013`) بآخر الخانات لإبقاء خطوط الناقل مستقرة وخضراء.
